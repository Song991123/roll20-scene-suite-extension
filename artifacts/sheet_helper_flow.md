# 시트 헬퍼가 동작해야 하는 흐름

## 전체 흐름

```text
[개발할 때]

실제 시트 HTML + CSS + 번역
            │
            ▼
하나의 공통 파서가 원본을 읽음
            │
            ├─ 입력칸 이름
            ├─ 굴림 버튼
            ├─ 반복해서 추가할 수 있는 구역
            ├─ 버튼이 참조하는 이름칸·수치칸
            ├─ 보너스·패널티 같은 선택지
            └─ 화면에 보이는 한글 이름과 표시 조건
            │
            ▼
시트에서 실제로 읽은 항목표 생성
            │
            ▼
배포용 10_sheet_helper.js 안에 자동 포함


[사용자가 Roll20에서 쓸 때]

사용자는 10_sheet_helper.js 하나만 설치
            │
            ▼
현재 캐릭터에 실제로 저장된 속성들을 읽음
            │
            ├─ 일반 속성
            └─ 사용자가 +Add로 만든 반복행 속성
            │
            ▼
10번 안의 항목표와 현재 저장값을 맞춰 봄
            │
            ├─ 분명히 일치함 → 해당 시트의 실제 굴림만 사용
            └─ 일치하지 않거나 구분할 수 없음 → 추측해서 굴리지 않고 안내
            │
            ▼
원본 버튼이 실제로 참조하는 값만 연결
            │
            ├─ 굴림 버튼 + 이름칸 + 수치칸 → 굴릴 항목
            ├─ 굴림 버튼 없는 메모·설명 → 굴림에서 제외
            └─ 굴림 버튼 없는 HP·MP 등 수치 → 굴림에서 제외
            │
            ▼
!!항목이름으로 원본 시트의 굴림식과 출력 모양을 그대로 실행
```

## 사용자가 `테스트` 기능을 추가했을 때

```text
시트의 +Add 버튼으로 새 기능 생성
            │
            ▼
Roll20이 새 행 ID와 함께 실제 속성을 저장

예시 모양
repeating_어떤구역_-새행ID_이름칸 = 테스트
repeating_어떤구역_-새행ID_수치칸 = 50
            │
            ▼
시트 헬퍼가 새 속성 추가 이벤트를 받음
            │
            ▼
해당 반복 구역의 원본 굴림 버튼 확인
            │
            ├─ 원본 버튼이 이름칸을 참조함
            ├─ 원본 버튼이 수치칸을 참조함
            └─ 원본 버튼의 전체 굴림식 보존
            │
            ▼
현재 행을 `테스트 50` 굴림으로 등록
            │
            ▼
!!테스트
            │
            ▼
현재 행 ID를 넣은 원본 시트 굴림 실행
```

행의 이름을 바꾸면 새 이름으로 다시 검색되고, 행을 지우면 굴림 목록에서도 빠져야 한다.

## 굴림과 일반 데이터는 이렇게 구분

```text
원본에 roll 버튼이 있는가?
            │
       ┌────┴────┐
       │         │
      예        아니오
       │         │
       ▼         ▼
버튼이 참조하는   메모·설명·HP·MP·기록 등
이름과 값을 연결  굴림 목록에서 제외
       │
       ▼
굴릴 항목 하나 생성
```

값이 숫자이거나 이름에 `skill`, `weapon` 같은 글자가 들어 있다는 이유만으로 굴림을 만들지 않는다. 실제 `roll` 버튼과의 연결만 기준으로 삼는다.

## 시트별로 달라지는 것과 달라지지 않는 것

달라지지 않는 것:

- 속성 읽기
- 반복행 찾기
- 이름 검색
- 선택지 처리
- 원본 굴림 실행
- 추가·수정·삭제 반영

시트별로 달라지는 것:

- 원본에서 실제로 사용한 필드 이름
- 원본 굴림 버튼의 식
- 원본 선택지와 표시 이름
- 반복 구역의 실제 구성

즉, 시트 A용 실행 코드와 시트 B용 실행 코드를 따로 만드는 방식이 아니다. 같은 실행 코드가 각 시트 원본에서 자동으로 뽑은 항목표를 읽으며, 실행 중 특정 게임이나 시트 이름으로 분기하지 않는다.

## 이 구조가 필요한 이유

Roll20의 Mod API는 실행 중인 시트의 HTML과 CSS를 직접 열어볼 수 없다. 대신 캐릭터에 실제로 저장된 속성은 읽을 수 있다.

그래서 시트 HTML은 배포 전에 공통 파서로 읽어서 10번 안에 넣고, Roll20 안에서는 현재 저장된 값과 사용자 추가 행만 결합한다. 사용자는 시트마다 다른 파일을 만들지 않고, 갱신된 10번 하나만 설치한다.

처음 보는 새 시트를 지원할 때도 실행 코드를 새로 만들지 않는다. 개발 단계에서 그 시트 원본을 같은 파서에 넣어 항목표를 추가하고 10번을 다시 배포한다.

## 이전의 잘못된 흐름과 지금 적용한 흐름

```text
[이전의 잘못된 부분]

다른 버전 시트에서 만든 항목표가 설치됨
            │
            ▼
항목표가 있다는 이유로 이전 반복행 추적을 끔
            │
            ▼
실제 시트의 `테스트` 행을 찾지 못함


[지금 적용한 방식]

실제 시트 원본에서 만든 항목표만 후보로 사용
            │
            ▼
현재 저장값과 분명히 일치할 때만 선택
            │
            ▼
실제 굴림 버튼에 연결된 반복행을 전부 생성
            │
            ▼
추가·수정·삭제를 즉시 반영
```

```text

│                                                                    │
│ 예시 시트 몇 개를 보고 변수명을 실행 코드에 직접 작성             │
│ san, luck, spot_hidden, rand_maddess, repeating_weapon ...         │
│                         │                                          │
│                         ▼                                          │
│ 현재 속성 이름을 보고 "아마 이 시트일 것"이라고 추정              │

│            ┌────────────┴────────────┐                             │
│            │                         │                             │

│            │                         │                             │

│                         ▼                                          │

│                         │                                          │
│                         ▼                                          │

│                         │                                          │

│            │                         │                             │
```

가장 중요한 차이는 “이름을 보고 기능을 추정”하지 않고 “원본 굴림 버튼이 실제로 무엇을 참조하는지”만 따른다는 점이다.

## 이전 구현과 현재 기준을 한눈에 비교

```text
이전 구현                                           현재 구현
──────────────────────────────────                 ──────────────────────────────────
예시 시트 몇 개를 보고                             지원할 실제 시트 원본을
변수명·광기식·보너스식을 직접 작성                 같은 공통 파서로 읽음
              │                                                   │
              ▼                                                   ▼
현재 캐릭터에 그 이름이 있는지 추정                 HTML + CSS + 번역 + roll 버튼 관계를 저장
              │                                                   │
       ┌──────┴──────┐                                            ▼
       │             │                              배포용 10번 하나에 인식 정보 포함
       ▼             ▼                                             │
아는 예시 구조   새 이름·다른 구조                                 ▼
직접 만든 식     누락 또는 오작동                    현재 캐릭터에 실제 저장된 값과 맞춤
       │                                                           │
       ▼                                                    ┌──────┴──────┐
원본에 없는 기능도                                          │             │
있는 것처럼 표시                                      분명히 일치     여러 후보가 비슷함
                                                               │             │
                                                               ▼             ▼
                                                   원본 버튼 그대로 실행   실행하지 않고 이유 안내
                                                               │             │
                                                               └──────┬──────┘
                                                                      ▼
                                                       추가·수정·삭제 때 다시 읽음
```

| 비교 항목 | 이전의 잘못된 방식 | 현재 방식 |
|---|---|---|
| 시트별 차이 | 실행 코드 안에 특정 변수명과 식을 직접 작성 | 원본 HTML·CSS·번역에서 자동 추출한 데이터로만 표현 |
| 굴림 실행 | 비슷한 굴림식을 새로 조립 | 원본 `roll` 버튼의 식과 출력 형식을 그대로 사용 |
| 사용자 추가 행 | 알려진 반복 구역 이름만 추적 | 원본 굴림 버튼과 연결된 모든 반복 구역을 행 ID로 추적 |
| 메모·HP·MP | 이름이나 숫자 모양으로 잘못 포함될 수 있음 | 원본 굴림 버튼이 연결되지 않았으면 굴림에서 제외 |
| 비슷한 시트 | 가장 비슷한 하나를 추측 | 현재 저장값만으로 구분되지 않으면 실행하지 않고 이유를 알림 |
| 번역 | 한글 별칭이 누락될 수 있음 | 번역 파일도 원본의 일부로 읽고 변경 여부에 포함 |
| 시트 교체 | 이전 인식 결과가 남을 수 있음 | 현재 저장값과 다시 대조하고 맞지 않으면 이전 캐시를 사용하지 않음 |
| 배포 | 시트마다 다른 JS를 만들 위험 | 사용자는 언제나 갱신된 `10_sheet_helper.js` 하나만 교체 |

## 기능 보존 대조

이번 구조 전환에서 “옛 코드가 하던 일”과 “현재 범용 경로로 확인된 일”을 분리한다.

| 기능 | 이전 코드 | 현재 상태 |
|---|---|---|
| 원본 굴림 실행 | 공통 파서와 CoC 고정 분기가 섞여 있었음 | 실제 원본에서 읽은 굴림만 실행하며 로컬 회귀 통과 |
| 사용자 추가 기능·무기·주문 | 알려진 반복 구역과 고정 필드에 의존하는 경로가 있었음 | 원본 roll 버튼 관계와 현재 행 ID로 추가·변경·삭제를 추적하며 로컬 회귀 통과 |
| 자유 주사위 | 시트별 고정 자유 주사위 경로가 섞여 있었음 | 원본에 자유 굴림 입력칸과 버튼이 있을 때만 `!!r` 실행하며 로컬 회귀 통과 |
| 보너스·패널티 | 미리 정한 CoC 변수와 식으로 보정하는 경로가 있었음 | 원본 선택 방식만 사용함. 공개 CoC 3주사위의 화면 차이는 Roll20에서 확인 전 |
| 성공수준·컷인 | 고정 변수명과 원본 결과 해석이 섞여 있었음 | 원본 결과가 돌려준 성공수준 필드만 해석하고, 08이 연결된 경우에만 컷인 전달 |
| 검색·상태·GM 점검 | 내부 이름이 화면에 섞이고 비슷한 시트를 추측할 수 있었음 | 사람용 이름과 현재값을 종류별로 모두 표시하고, 구분되지 않으면 실행하지 않음 |
| 화자 전환 | 별도 기능으로 동작 | 현재 공통 실행부에 보존, 로컬 회귀 통과 |
| `:hp+3` 같은 수치 변경 | CoC 변수명 사전과 추정 분류에 의존 | `:항목이름±수치/주사위` 형식으로 명시된 경우에만, 현재 시트에서 하나로 찾은 실제 수치를 변경하며 로컬 회귀 통과 |
| 자동 중상·빈사·광기 체크 | 특정 CoC 변수명과 직접 만든 규칙에 의존 | 같은 자원 묶음의 사람용 표시명과 원본 상태·굴림으로 역할을 찾는다. 최대 체력 기준 중상·빈사, 시작 이성 기준 장기적 광기, 단일 5점 손실 뒤 지능 성공 시 일시적 광기를 로컬 회귀로 확인 |
| 고정 행운 결정·명중부위·특수 주사위 | 원본에 없어도 실행 코드가 만들어 낼 수 있었음 | 삭제. 원본에 실제 굴림이 있을 때만 일반 굴림 검색으로 나타남 |

자동 상태 처리도 예전 고정값 코드를 다시 켠 것이 아니다. 대상 시트에서 필요한 현재값·시작값·최대값·상태·굴림을 각각 하나로 찾을 수 있을 때만 동작하며, 모호하거나 없는 항목은 건드리지 않는다.

## 이성 세 값이 이어지는 흐름

```text
같은 이성 자원 묶음에서 읽은 값
       │
       ├─ 현재 이성 ──▶ 이성 판정 목표값·손실 뒤 값
       ├─ 시작 이성 ──▶ 진행 중 변화율·장기적 광기 1/5 기준
       └─ 최대 이성 ──▶ 99-크툴루 신화, 회복 상한

표시: 현재 40 / 시작 50 (80%) / 최대 99

단일 손실 5 이상 ──▶ 장기적 광기 꺼짐 ──▶ 원본 지능 판정
                                              │
                                              └─ 성공 ──▶ 원본 일시적 광기 활성화

시작 대비 누적 손실 1/5 이상 ──▶ 원본 장기적 광기 활성화 ──▶ 위 지능 판정 생략
```

## 10번 안에서 실제로 일어나는 순서

```text
빌드 시점
실제 시트 원본 ──공통 파서──▶ 시트에서 읽은 항목 ──자동 포함──▶ 10_sheet_helper.js 하나

Roll20 실행 시점
현재 캐릭터 저장값 ──대조──▶ 시트 인식 ──행 ID 결합──▶ 현재 굴림 목록
                                                   │
사용자 명령 `!!테스트` ──이름 검색──────────────────┘
                                                   │
                                                   ▼
                                      원본 roll 버튼을 현재 값으로 실행
```

여기서 공통 파서는 변수명 자체를 미리 알고 있지 않다. `attr_...` 입력칸과 `type="roll"` 버튼의 실제 연결을 읽는다. 시트마다 달라지는 이름은 실행 코드의 조건문이 아니라 자동 생성된 인식 정보에만 들어간다.

## 결과와 컷인이 이어지는 흐름

```text
!!굴릴항목이름
        │
        ▼
현재 시트에서 읽은 원본 roll 버튼 실행
        │
        ▼
Roll20이 실제 주사위 결과 메시지 반환
        │
        ├─ success / hard / extreme / roll·roll1 등의 값이 있음
        │          │
        │          ▼
        │   반환값만으로 성공수준 계산
        │          │
        │          ▼
        │   08 컷인이 설치되어 있고 연결돼 있으면 판정 컷인 실행
        │
        └─ 성공수준 값이 없음
                   │
                   ▼
            일반 굴림 결과로만 전달
```

이 과정에서도 `san`, `spot_hidden` 같은 속성명을 새로 추정하지 않는다. 성공수준은 원본 굴림이 실제로 반환한 필드가 있을 때만 계산한다.
