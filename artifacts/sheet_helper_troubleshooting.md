# 시트 헬퍼 재발 방지 기록

## 발생한 문제

- 실제 Sheet Sandbox에 적용한 `coc.html`과 다른 버전의 시트 파일로 항목표를 만들었다.
- 항목표가 하나 있다는 이유만으로 현재 캐릭터와 일치하는지 확인하지 않고 강제로 적용했다.
- 항목표가 적용되면 기존 반복행 수집 결과를 전부 무시했다.
- 그 결과 시트의 `+Add`로 만든 `테스트` 기능이 실제 속성으로 존재해도 검색과 굴림에서 빠졌다.
- 예시 시트에서 본 CoC 변수명과 굴림식을 10번에 직접 넣어, 원본에 없는 기능까지 있는 것처럼 보일 수 있었다.

1순위 검증 기준은 `천량성 커스텀 CoC` 원본의 `coc.html`과 `coc.css`다. 이 원본은 속성 329개, 굴림 90개, 선택 방식 424개다. 개발 방에서 별도로 확인한 마렌 헤윰 커스텀 CoC는 속성 187개, 굴림 72개, 선택 방식 374개다. 187 / 72 / 374를 천량성 시트의 수치로 보았던 해석만 폐기하며, 마렌 헤윰 시트 자체는 별도 호환 대상으로 유지한다.

현재 Roll20 라이브 기준으로 천량성 시트의 상태, 검색, 일반 및 보너스 굴림, 실시간, 요약, `!!r`, 사용자 추가 반복 기능치를 확인했다. Bloody Mary Castle은 일반/펄프 실시간 선택과 실제 굴림을 확인했다. 마렌 헤윰 시트, 자체제작 호질, Roll20 공개 CoC 7판은 로컬 검증만 완료했다.

Sheet Sandbox에서 HTML/CSS를 교체한 직후에는 Mod API가 이전 시트의 기본값과 계산식을 들고 있을 수 있다. 시트 파일을 바꾼 뒤 Mod API를 한 번 재시작하고 `!!점검` 또는 `캐릭터별 현황 보기`의 `시트 다시 읽기`로 현재 저장 항목을 다시 확인한다. 재시작 전 발생한 없는 시트 필드 오류를 새 코드의 실행 결과로 판정하지 않는다.

## 직접 원인

```text
다른 버전 시트로 만든 항목표
        +
항목표 하나면 무조건 현재 시트라고 판정
        +
항목표 경로와 이전 반복행 경로를 배타적으로 처리
        =
사용자 추가 반복행 누락
```

## 고칠 때 지켜야 할 순서

1. 테스트 중인 실제 HTML/CSS의 해시를 기록한다.
2. 그 실제 원본을 공통 파서에 넣는다.
3. 파서 결과에 반복 구역, 이름칸, 수치칸, 원본 roll 값이 들어 있는지 확인한다.
4. 현재 캐릭터의 실제 `repeating_<구역>_<행ID>_<필드>` 속성과 결합한다.
5. 원본 roll 버튼에 연결된 행만 굴림 목록으로 만든다.
6. 추가·이름 변경·수치 변경·삭제 이벤트마다 캐시가 갱신되는지 검사한다.
7. 원본 roll 버튼에 연결되지 않은 메모·설명·HP·MP가 굴림 목록에 들어오지 않는지 검사한다.
8. 실제 Sheet Sandbox에서 같은 원본을 올리고 결과를 눈으로 확인한다.

현재 자동 검사는 전역 속성 이름이 많이 겹쳐도 실제 반복 구역이 다른 가짜 후보를 함께 넣는다. `repeating_science` 행이 있는 캐릭터가 `repeating_skills` 후보로 잘못 선택되지 않아야 통과한다.

## 금지 사항

- `san`, `luck`, `spot_hidden` 같은 특정 시트 변수명을 범용 실행 코드에 추가하지 않는다.
- 특정 시트의 광기식·보너스식·템플릿을 비슷하게 다시 만들지 않는다.
- 원본에 없는 속성을 생성해서 기능을 흉내 내지 않는다.
- 항목표가 하나라는 이유만으로 모든 캐릭터에 강제로 적용하지 않는다.
- 다른 버전·비슷한 이름의 시트를 실제 테스트 원본 대신 사용하지 않는다.
- 합성 테스트 통과만으로 실제 시트 호환 완료라고 기록하지 않는다.

## 필수 회귀 검사

```text
사용자 기능 `테스트` 추가 → !!테스트 실행 성공
       ↓
이름 변경 → 새 이름만 검색됨
       ↓
수치 변경 → 새 수치로 굴림
       ↓
행 삭제 → 검색·굴림에서 제거

사용자 무기 추가 → 원본 무기 굴림 실행
사용자 주문 추가 → 원본 주문 출력 실행

원본 roll 버튼에 연결되지 않은 메모·설명 → 굴림 목록에 없음
원본 roll 버튼에 연결되지 않은 HP·MP → 굴림 목록에 없음
원본에 없는 특수 굴림 → 표시되지 않음
```

## 완료 판정

- 코드 경로 확인
- 자동 회귀 검사 통과
- 실제 원본 해시 일치
- Sheet Sandbox 화면과 채팅 결과 확인

네 가지가 모두 확인되기 전에는 완료 또는 배포로 표시하지 않는다.

## 같은 실수를 막는 점검표

### 원본을 추가하거나 바꿀 때

- 실제 검증할 HTML·CSS·번역 파일 경로와 해시를 먼저 기록한다.
- 번역 파일도 파서 입력과 변경 감지 해시에 포함한다.
- 기존 생성 도구의 원본 읽기 함수를 재사용한다. 비슷한 새 로더를 따로 만들지 않는다.
- 생성 결과의 속성·굴림·선택 방식 개수를 이전 보고서에서 복사하지 않고 다시 센다.
- 비슷한 커스텀 시트끼리 저장 구조가 같으면 자동으로 하나를 고르거나 수동 선택 화면을 만들지 않는다. 실행하지 못한 이유를 알린다.

### Roll20에서 시트를 교체했을 때

- 현재 캐릭터의 저장 구조를 새로 읽고 이전 캐시와 다시 대조한다.
- 맞지 않으면 이전 캐시를 사용하지 않는다.
- 구조가 같아 자동 구분이 불가능해도 캐릭터별 시트 선택값을 만들지 않는다.
- 이 과정에서 기존 사용자 설정과 다른 Scene Suite 상태는 초기화하지 않는다.

### 명령을 실행할 때

- `!!항목`은 현재 시트에서 읽은 원본 굴림만 검색한다.
- `!!실시간`, `!!요약`, `!!일시적`, `!!장기적`도 원본 버튼명·선택명에서 찾는다.
- 같은 이름이 여러 개면 첫 번째 것을 임의 실행하지 않고 검정 선택 버튼을 보여준다.
- 자유 주사위는 허용된 주사위 문법을 통과한 식만 원본 자유 굴림 입력칸에 넣는다.
- 원본에 자유 굴림 입력칸이 없으면 다른 시트의 속성을 만들어 대신 굴리지 않는다.
- 보너스·패널티는 통합 선택형, 분리 버튼형, 원본 질문형을 모두 원본 데이터로 구분한다.

### 사용자 화면을 만들 때

- `mode-...`, 행 ID, 내부 속성명, 원시 선택값을 그대로 노출하지 않는다.
- 기능치·무기·주문·광기·기타 굴림은 원본의 표시 이름과 실제 연결 관계로 분류한다.
- 분류가 확실하지 않으면 `기타 굴림`으로 두고 기능을 새로 추측하지 않는다.

## 증상별 확인 순서

| 증상 | 먼저 확인할 원인 | 고치는 위치 |
|---|---|---|
| 사용자가 추가한 `테스트`를 못 찾음 | 현재 저장 구조가 원본 반복 구역과 맞는지, 해당 구역에 원본 roll 버튼이 있는지 | 시트 인식과 반복행 결합 경로 |
| `실시간`·`요약`을 못 찾음 | 한국어 번역 파일이 생성 입력과 해시에 포함됐는지 | 기존 원본 읽기 함수와 임베드 생성 도구 |
| 광기 종류가 하나로 뭉침 | 원본의 버튼별·선택지별 이름을 버리고 임의 분류했는지 | 원본 이름·선택 방식 검색 경로 |
| 보너스·패널티가 엉뚱하게 굴러감 | 해당 시트의 실제 구조가 통합형인지 분리형인지 원본에서 읽었는지 | 원본 선택 방식 실행 경로 |
| `mode-...` 같은 코드가 보임 | 사용자 표시용 이름과 내부 식별자를 분리하지 않았는지 | 상태·검색·관리 핸드아웃 출력 |
| 시트 교체 뒤 이전 항목이 남음 | 캐시를 현재 속성으로 다시 검증했는지 | 캐시 무효화와 현재 저장값 재검증 |

## 자동검사에서 반드시 깨져야 하는 회귀

다음 중 하나라도 다시 생기면 검사는 실패해야 한다.

1. 번역 파일 없이 공개 시트의 한글 굴림 이름을 찾는 척한다.
2. 실제 반복 구역이 다른 유사 시트를 선택한다.
3. 사용자 추가 행의 추가·이름 변경·수치 변경·삭제 중 하나를 놓친다.
4. 원본 roll 버튼이 없는 메모·HP·MP를 굴림으로 만든다.
5. 일부 이름이 여러 개 맞는데 첫 항목을 자동 실행한다.
6. 자유 주사위에 채팅 명령이나 닫히지 않은 식이 들어가도 실행한다.
7. 시트에 없는 광기·행운·명중부위·보너스 방식을 만들어 보여준다.

## 구조 전환 중 추가로 발견한 문제

### 검사가 배포본과 다른 코드를 실행한 문제

이전 자동검사는 배포본에서는 꺼진 CoC 전용 추정 기능을 검사 안에서만 강제로 켰다. 그 상태에서 나온 통과 결과는 실제 배포 경로의 증거가 아니다.

수정 기준:

- 핵심 회귀 검사는 배포용 `10_sheet_helper.js`를 설정 변조 없이 실행한다.
- 실제로 포함된 시트 원본 5종을 같은 런타임에 등록한 상태로 검사한다.
- 예전 고정 변수명 경로가 없어도 사용자 반복행, 원본 선택 방식, 자유 굴림, 결과 컷인이 동작해야 한다.

### 원본 굴림 결과가 성공수준을 건너뛴 문제

원본 버튼 실행에는 결과 추적용 표식이 붙었지만, 원본에서 읽은 굴림이라는 이유로 성공수준 계산을 건너뛰고 있었다. 따라서 채팅에는 주사위가 나와도 성공, 어려운 성공, 극단적 성공 컷인으로 이어지지 않을 수 있었다.

수정 기준:

- 반환된 채팅 메시지에 실제 `success`, `hard`, `extreme`, `roll` 값이 있을 때만 성공수준을 계산한다.
- 캐릭터 시트의 속성명이나 굴림식을 새로 만들지 않는다.
- 보너스/패널티는 원본 선택 방식의 사람이 읽는 이름과 실제 반환 주사위만 사용한다.
- 원본에 성공수준 값이 없는 굴림은 성공 단계를 추측하지 않고 일반 굴림 결과로만 전달한다.

### 내부 이름이 사용자 목록에 나온 문제

실행용 검색 별칭과 화면 표시명을 같은 배열로 사용해 `roll-...`, `repeating_....roll-...`, `luck_check` 같은 내부 이름이 `!!상태`에 섞였다.

수정 기준:

- 내부 이름은 실행 항목을 찾기 위한 별칭으로만 보관한다.
- 상태, 검색, `캐릭터별 현황 보기`, 선택 버튼에는 원본의 번역명, 정적 제목, 사용자 입력 행 이름만 사용한다.
- 사람이 읽을 이름이 없는 굴림은 목록에서 숨긴다. 같은 표시명이 여러 개면 내부 코드를 붙이지 않고 `선택 1`, `선택 2`로만 구분한다.

### 공개 CoC 7판의 3개 주사위 버튼

해당 원본에는 1개 주사위 버튼과 3개 주사위 버튼이 따로 있지만, 3개 주사위 버튼 자체에는 보너스/패널티의 부호와 개수가 들어 있지 않다. 따라서 로컬 검사만으로 네 명령이 Roll20 화면에서도 서로 다르게 표시된다고 단정하면 안 된다.

수정 기준:

- 코드는 원본 3개 주사위 버튼만 실행하고, 명령에 적은 방식은 결과 성공수준을 고르는 데만 사용한다.
- 실제 Roll20 표시가 기대와 같은지는 Sheet Sandbox에서 네 명령을 각각 눈으로 확인한다.
- 실검증 전에는 문서에 완전 지원으로 표시하지 않는다.

### 옛 고정 기능을 지우면서 기능까지 사라진 문제

CoC 고정 변수명과 직접 만든 공식을 제거하는 과정에서 `:hp+3` 수치 변경, 자동 중상·빈사, 이성 감소 뒤 지능 판정·광기 체크 같은 기능도 함께 빠졌다. 옛 구현이 잘못됐다는 이유로 이 기능들이 현재도 동작한다고 적으면 안 된다.

수정 기준과 현재 복원 방식:

- 기능을 다시 넣을 때 `hp`, `san`, `temp_insane` 같은 특정 시트 변수명 목록을 복구하지 않는다.
- 실제 원본에서 읽은 표시명·같은 자원 묶음·입력칸·상태 선택지·굴림 관계만으로 대상을 고른다.
- 일반 채팅의 `hp+3`은 변경 명령이 아니다. `:항목이름+3`처럼 명시적인 형식이고 현재 시트에서 하나로 찾은 수치만 변경한다.
- 현재 이성, 시작 이성, 최대 이성을 합치지 않는다. 시작 이성은 변화율과 장기적 광기 기준, 최대 이성은 회복 상한이다.
- 시작 이성 대비 1/5 누적 손실은 장기적 광기를 활성화하고, 단일 5점 손실은 장기적 광기가 아닐 때만 지능 판정을 실행한다. 지능 성공 시 일시적 광기를 활성화한다.
- 최대 체력 절반 이상의 단일 피해는 중상, 중상 상태의 체력 0은 빈사를 활성화한다.
- 필요한 역할이 없거나 여러 개면 임의로 고르지 않고 자동 처리 생략 사유를 GM에게 알린다.
- 기존 Roll20 `state` 전체를 초기화하지 않는다. 새 인식 정보와 맞지 않는 캐시만 무효화한다.
- 복원 뒤에는 기존 매크로, 관리 핸드아웃, 판정 컷인 연결을 포함한 기능 보존표를 다시 검사한다.

필수 이성 회귀:

1. 최대 99, 시작 50, 현재 41→40: 장기적 광기 켜기, 지능 판정 0회.
2. 최대 99, 시작 50, 현재 50→45: 지능 판정 1회, 성공하면 일시적 광기 켜기.
3. 장기적 광기 활성 상태에서 5 이상 손실: 지능 판정 0회.
4. 최대 이성만 변경하거나 현재 이성이 회복됨: 광기 자동 판정 0회.
5. `:이성-5`와 직접 속성 변경 모두 같은 규칙을 정확히 한 번만 실행.
