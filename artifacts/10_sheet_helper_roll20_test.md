# 10 Sheet Helper Roll20 수동검증

이 문서는 배포 설명서가 아니다. `10_sheet_helper.js`를 실제 Roll20 Sheet Sandbox에서 확인하기 위한 수동검증표다.

검증 기준 파일

- `public/scripts/10_sheet_helper.js` 0.6.6
- 1순위 검증 원본은 `천량성 커스텀 CoC`의 `coc.html`과 `coc.css`다. 추출 결과는 속성 329개, 굴림 90개, 선택 방식 424개다.
- 마렌 헤윰 커스텀 CoC는 속성 187개, 굴림 72개, 선택 방식 374개인 별도 호환 시트다. 천량성 시트의 다른 버전이나 대체 원본으로 취급하지 않는다.
- 현재 10번에는 위 두 시트와 자체제작 호질, Bloody Mary Castle, Roll20 공개 CoC 7판까지 원본 5종이 포함되어 있다.
- inSANe와 Magical Fury는 원본 추출 참고 대상이며, 현재 10번의 Roll20 실행 대상으로 기록하지 않는다.
- `dice.js`는 마지막 충돌 확인에서만 사용하고 수정하지 않는다.

로컬 문법 검사나 모의 실행은 Roll20 동작 확인으로 기록하지 않는다. 아래 항목은 전용 테스트 방에서 직접 실행한 뒤 체크한다.

현재 라이브 확인 기록

- 천량성 커스텀 CoC: `!!상태`, `!!검색`, 일반 및 보너스 굴림, `!!실시간`, `!!요약`, `!!r` 실행 확인
- 천량성 커스텀 CoC의 사용자 추가 행: `천량성추가기능`을 목표 50, 어려운 성공 기준 25, 극단적 성공 기준 10으로 읽어 실제 굴림 확인
- 마렌 헤윰 커스텀 CoC: 별도 시트로 로컬 호환 확인, 최종 저장본 라이브 미검증
- Bloody Mary Castle: `!!실시간`에서 일반/펄프 선택 버튼을 표시하고 일반 실시간 광기 굴림 실행 확인
- 자체제작 호질, Roll20 공개 CoC 7판: 로컬 검증만 완료

## 0. 준비와 증거 기록

- [x] 대상 시트의 실제 HTML, CSS, 번역 파일과 10번의 SHA256을 기록한다.
- [x] Sheet Sandbox에 대상 시트를 적용하고 캐릭터 시트를 한 번 연다.
- [x] Sheet Sandbox에서 HTML/CSS를 바꿨다면 Mod API를 한 번 재시작한 뒤 검사한다.
- [ ] 배포용 `10_sheet_helper.js` 하나만 설치해 단독 사용을 먼저 확인한다.
- [x] 샌드박스에 오류 없이 `ready`가 뜬다.
- [ ] 테스트 캐릭터와 현재 페이지의 대표 토큰 하나를 준비한다.
- [ ] PL 계정에는 테스트 캐릭터의 조작 권한을 준다.
- [x] 실제 화면이나 채팅을 확인하지 못한 항목은 통과로 체크하지 않는다.

## 1. 현재 시트 인식

다섯 원본을 한 번씩 적용해 아래 명령을 확인한다.

```text
!!점검
!!관리
!!상태
```

- [ ] `!!점검`은 GM에게만 보인다.
- [ ] `원본 시트`, `현재 캐릭터`, `검색용 이름` 수를 서로 다른 값으로 표시한다.
- [ ] 반복행을 아직 채우지 않았다면 현재 실행 수가 원본 정의 수보다 적어도 오류로 보지 않는다.
- [ ] 현재 캐릭터와 맞는 원본만 후보가 된다.
- [ ] 저장 구조가 같아 자동 구분할 수 없는 원본은 GM에게 검정 선택 버튼을 보여준다.
- [ ] GM이 고른 뒤에는 해당 원본의 굴림만 표시한다.
- [ ] 다른 시트로 바꾸면 맞지 않는 이전 선택을 강제로 사용하지 않는다.
- [ ] `!!상태`와 관리 화면에 내부 속성명, 행 ID, `roll-...`, `repeating_...`, `mode-...`, 원시 선택값이 나오지 않는다.

## 2. 원본 굴림 실행

각 시트의 `!!상태`에 실제로 표시된 굴림 이름을 하나 고른다. 문서에 적힌 예시 이름이 아니라 현재 화면에서 읽힌 이름을 사용한다.

```text
!!굴릴항목이름
!!비밀 굴릴항목이름
!!굴릴항목이름 선택할이름
!!검색 굴릴항목이름의일부
```

- [ ] 정확한 이름은 해당 원본 버튼을 한 번만 실행한다.
- [ ] 비밀 굴림은 GM에게만 결과를 보낸다.
- [ ] 선택할 이름은 현재 시트에 실제로 있는 선택 방식만 받는다.
- [ ] 이름 일부가 하나만 맞으면 그 항목을 바로 실행한다.
- [ ] 이름 일부가 여러 항목과 맞으면 임의 실행하지 않고 검정 선택 버튼을 보여준다.
- [ ] 선택 버튼을 누르면 고른 항목만 한 번 실행한다.
- [ ] 원본에 없는 굴림이나 선택 방식을 적으면 샌드박스를 멈추지 않고 오류만 안내한다.
- [ ] 굴림 결과의 이름, 식, 출력 틀은 원본 시트 버튼을 직접 눌렀을 때와 같다.

## 3. 보너스와 패널티 선택 방식

현재 시트에 실제로 보이는 선택 방식만 사용한다.

```text
!!굴릴항목이름 원본에표시된선택이름
```

- [ ] 기본·보너스·패널티가 하나의 선택칸에 든 시트는 그 원본 선택값을 사용한다.
- [ ] 보너스·패널티가 질문이나 별도 버튼으로 나뉜 시트는 해당 원본 구조를 사용한다.
- [ ] 원본에 없는 보너스 2나 패널티 2를 코드가 보충하지 않는다.
- [ ] Roll20 공개 CoC 7판의 주사위 1개 버튼과 3개 버튼은 원본 그대로 호출한다.
- [ ] 공개 CoC 7판의 네 보너스·패널티 표현이 실제 화면에서 서로 구분되는지는 각각 눈으로 확인하고 따로 기록한다.

## 4. 사용자가 추가한 반복행

현재 시트에서 `+Add`로 추가할 수 있고 원본 roll 버튼이 연결된 구역 하나를 고른다. 기능, 무기, 주문 중 시트에 실제로 있는 구역이면 된다.

1. 이름 `테스트`, 수치 `50`인 행 A를 추가한다.
2. `!!테스트`와 `!!검색 테스트`를 실행한다.
3. 수치를 `65`로 바꿔 다시 실행한다.
4. 이름을 `테스트변경`으로 바꾼다.
5. 같은 이름의 행 B를 하나 더 만든다.
6. 두 행의 순서를 바꾼다.
7. 행 B를 삭제한다.
8. 마지막으로 행 A도 삭제한다.

- [ ] 추가 직후 `테스트 50`을 현재 행의 원본 식으로 실행한다.
- [ ] 수치 변경 뒤 재설치 없이 65가 반영된다.
- [ ] 이름 변경 뒤 예전 이름은 사라지고 새 이름만 검색된다.
- [ ] 같은 이름 두 행은 임의 실행하지 않고 사람이 읽는 선택 버튼으로 구분한다.
- [ ] 행 ID나 내부 속성 키를 사용자 화면에 표시하지 않는다.
- [ ] 재정렬 뒤에도 두 행의 값이 서로 바뀌지 않는다.
- [ ] 행을 삭제하면 해당 검색과 실행 대상도 사라진다.
- [ ] 무기나 주문 반복행이 있는 시트에서는 같은 순서로 한 번 더 확인한다.
- [ ] 위 과정은 먼저 자동 갱신만으로 확인한다. 문제가 있을 때만 `!!새로고침`을 실행해 자동 갱신 문제와 인식 문제를 구분한다.

## 5. 굴림이 아닌 데이터 제외

- [ ] 원본 roll 버튼이 연결되지 않은 메모와 설명은 굴림 목록에 나오지 않는다.
- [ ] 원본 roll 버튼이 연결되지 않은 HP, MP, 탄약 같은 수치는 굴림 목록에 나오지 않는다.
- [ ] 수치가 숫자이거나 이름에 `skill`, `weapon` 같은 글자가 있다는 이유만으로 굴림을 만들지 않는다.
- [ ] 반대로 이성처럼 원본 roll 버튼이 실제로 연결된 수치는 해당 원본 굴림으로 표시될 수 있다.
- [ ] 원본에 없는 행운 결정, 명중부위, 광기 방식은 만들어 표시하지 않는다.

## 6. 광기 이름과 자유 주사위

현재 시트에 같은 이름의 원본 굴림이 있을 때만 다음 명령을 사용한다.

```text
!!실시간
!!요약
!!일시적
!!장기적
```

- [ ] 현재 시트에 있는 이름만 원본 굴림을 실행한다.
- [ ] 없는 이름은 다른 시트의 식을 대신 실행하지 않는다.
- [ ] 일반·펄프·시대별 버튼이 나뉜 시트는 현재 저장값과 표시 조건에 맞는 후보만 보인다.

현재 시트 원본에 자유 굴림 입력칸과 버튼이 있을 때만 다음을 확인한다.

```text
!!r 2d6+1
!!비밀 r 2d6+1
!!r 101d6
!!r 1d100001
!!r 1d6]] {{subject=침입
```

- [ ] 공개 자유 굴림은 원본 시트의 출력 모양으로 한 번 실행된다.
- [ ] 비밀 자유 굴림은 GM에게만 보인다.
- [ ] 개수·면수·길이 제한을 넘거나 닫히지 않은 식은 실행하지 않는다.
- [ ] 잘못된 식 뒤에도 샌드박스와 다음 정상 명령이 계속 동작한다.
- [ ] 자유 굴림 원본이 없는 시트에는 `!!r` 사용법이나 버튼을 표시하지 않는다.

## 7. PL 상태와 검색 화면

```text
!!도움말
!!상태
!!검색 이름
```

- [ ] PL 사용법은 명령과 설명을 표로 구분하고 GM 전용 설정을 섞지 않는다.
- [ ] 자유 굴림 원본이 없는 캐릭터의 PL 사용법에는 `!!r`을 표시하지 않는다.
- [ ] PL은 자신이 조작할 수 있는 캐릭터의 굴림과 계산된 현재 수치만 본다.
- [ ] 굴림은 기능치·판정, 무기, 주문, 광기, 기타 굴림처럼 사람이 이해할 수 있는 범주로 정리된다.
- [ ] 분류 근거가 부족한 항목은 기능을 추측하지 않고 기타 굴림으로 둔다.
- [ ] 계산 가능한 최대 수치는 계산 결과로 보여주고 `floor(...)`, `@{...}` 같은 내부 식을 노출하지 않는다.
- [ ] 검색 결과의 굴리기 버튼은 같은 항목을 한 번만 실행한다.

## 8. 권한과 오류 처리

- [ ] 조작 권한이 없는 PL은 다른 캐릭터의 굴림을 실행할 수 없다.
- [ ] 사용할 캐릭터가 없거나 여러 명인데 대상을 정하지 않았으면 선택 방법을 안내한다.
- [ ] GM 전용 명령을 PL이 실행하면 GM 전용이라는 안내만 보낸다.
- [ ] 잘못 인코딩된 선택 버튼, 빈 이름, 없는 이름은 샌드박스를 멈추지 않는다.
- [ ] 오류 뒤 정상적인 `!!굴릴항목이름`을 바로 실행할 수 있다.

## 9. 업데이트와 시트 교체

- [ ] 기존 10번에서 사용자 설정, 관리 핸드아웃 설정, 판정 컷인 연결을 준비한다.
- [ ] 갱신된 10번으로 교체해도 기존 Roll20 `state`와 위 설정이 유지된다.
- [ ] 번역 이름이 바뀌어도 같은 원본 굴림의 컷인 연결이 유지된다.
- [ ] 현재 캐릭터와 맞지 않는 이전 시트 선택은 버린다.
- [ ] 시트 교체 뒤 새 시트에 없는 이전 굴림은 상태·검색·관리 화면에서 사라진다.

## 10. 판정 결과와 컷인 연결

먼저 10번만 설치한다.

- [ ] 컷인 연결 기능이 없더라도 원본 굴림과 결과는 정상 동작한다.
- [ ] 08 컷인이 없으면 컷인 전용 버튼을 일반 기능처럼 표시하지 않는다.

그다음 `08_cutin_director.js`를 함께 설치하고 결과 확인용 카드를 준비한다.

- [ ] 모든 판정 결과 연결은 판정 항목을 묻지 않고 성공 단계만 고른다.
- [ ] 특정 판정 연결은 현재 시트에서 읽은 굴림만 선택지에 보여준다.
- [ ] 원본 결과에 `success`, `hard`, `extreme`, `roll`, `roll1` 등 실제 성공수준을 계산할 값이 있을 때만 성공 단계를 정한다.
- [ ] 원본 결과에 성공수준 값이 없으면 성공이나 실패를 추측하지 않는다.
- [ ] 기본, 보너스, 패널티 굴림에서 화면에 표시된 최종 주사위와 컷인이 일치한다.
- [ ] 비밀 굴림은 공개 컷인을 재생하지 않는다.
- [ ] 시트에서 원본 버튼을 직접 눌렀을 때도 결과를 포착할 수 있는지 별도로 확인한다.
- [ ] 연결 해제나 카드 삭제 뒤 샌드박스가 멈추지 않는다.

## 11. dice.js 충돌 확인

`dice.js`는 수정하지 않는다. 10번과 명령 영역이 겹치지 않는지만 확인한다.

```text
1d6
choice[빨강,파랑]
!!굴릴항목이름
!!r 2d6+1
```

- [ ] 전역 이름 재선언 오류가 없다.
- [ ] 일반 주사위와 choice는 기존 주사위 코드에서 한 번만 나온다.
- [ ] 시트 굴림과 자유 굴림은 10번에서 한 번만 나온다.
- [ ] `hp+3`, `이성-1` 같은 일반 채팅은 시트 값을 바꾸지 않는다.

## 12. 삭제한 이전 고정 경로

이전 문서의 3~15장은 특정 CoC 변수명, 고정 판정 63개, 고정 무기·주문·방어구, `!시트 설정|coc7` 경로를 현행 지원 범위처럼 검사했다. 이 경로는 현재 범용 검증 대상이 아니므로 삭제했다.

현재 완료 판정에는 다음 증거만 사용한다.

- 실제 지원 시트 원본에서 읽힌 굴림과 선택 방식
- 현재 캐릭터에 실제로 저장된 값
- 사용자가 추가·수정·삭제한 반복행
- 원본 결과에서 실제로 반환된 성공수준 값
- Sheet Sandbox에서 눈으로 확인한 채팅과 화면
