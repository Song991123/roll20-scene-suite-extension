# Scene Suite 10 시트 헬퍼 요구사항

이 문서는 시트 헬퍼를 수정할 때 반드시 지켜야 할 기준이다. 구현 편의를 이유로 아래 기준을 바꾸지 않는다.

## 1. 기본 원칙

- 사용자가 설치하는 파일은 `10_sheet_helper.js` 하나다.
- 사용자가 시트마다 다른 보조 파일을 만들거나 교체하지 않는다.
- 브라우저 확장, 유저스크립트, 별도 웹페이지 실행을 필수로 요구하지 않는다.
- 시트마다 A용·B용 실행 코드를 따로 만들지 않는다. 모든 시트는 같은 수집·검색·실행 경로를 사용한다.
- 시트별 차이는 원본 HTML/CSS/번역에서 자동으로 읽은 필드·굴림 버튼·선택지 데이터로만 표현한다.
- 특정 예시 시트의 변수명, 굴림식, 템플릿을 실행 코드에 직접 적지 않는다.
- 실제 시트에서 찾지 못한 속성이나 굴림을 추측해서 만들거나 실행하지 않는다.
- 업데이트해도 기존 Roll20 `state`, 선택한 시트, 매크로, 관리 핸드아웃 ID, 판정 컷인 연결이 사라지지 않아야 한다.
- 파일 상단의 설치 옵션은 새 파일을 만들 때 이전과 같은 값을 선택한다. 코드에 적힌 설치 옵션까지 Roll20 `state`에 저장된다고 잘못 안내하지 않는다.

## 2. 원본 시트 읽기

- 원본의 `name="attr_..."`, `type="roll"`, 반복 구역, 선택지, 번역, 표시 조건을 일반 파서 하나로 읽는다.
- 파서가 읽을 변수명은 미리 목록으로 정하지 않는다.
- 굴림식과 출력 형식은 원본 버튼의 값을 사용한다. 비슷해 보이는 식을 새로 조립하지 않는다.
- 원본에 없는 행운 결정, 명중부위, 광기, 보너스·패널티 방식 등은 표시하거나 실행하지 않는다.
- 시트가 바뀌었거나 인식 결과가 모호하면 이전 시트의 값을 억지로 적용하지 않는다.

## 3. 사용자가 추가하는 항목

- 시트 안의 `+Add`로 생성한 기능, 무기, 주문 등 반복행을 자동으로 찾는다.
- 새 행 추가, 이름 변경, 수치 변경, 삭제를 다시 설치하지 않고 반영한다.
- 행 이름은 사용자가 입력한 실제 값을 검색명과 버튼명으로 사용한다.
- 같은 반복 구역의 원본 굴림 버튼이 참조하는 이름칸·수치칸·선택지만 해당 행에 연결한다.
- 반복 구역 이름이나 `skillname`, `weapon_name`, `magic_name` 같은 필드명을 고정 목록으로 정하지 않는다.
- 사용자가 추가한 항목도 원본 시트와 같은 굴림식·보너스·패널티 방식·출력 디자인으로 실행한다.

## 4. 굴림 항목과 일반 데이터 분리

- 원본의 굴림 버튼에 연결된 항목만 굴림 목록에 넣는다.
- 메모, 설명, 배경, 기록처럼 굴리지 않는 텍스트는 굴림 목록에 넣지 않는다.
- 원본 굴림 버튼에 연결되지 않은 HP, MP, 이성, 탄약 같은 소모·회복 수치는 굴림 목록에 넣지 않는다.
- 일반 수치는 상태·검색 화면에서 별도 수치 항목으로 보여줄 수 있지만, 원본에 굴림 버튼이 없으면 굴리지 않는다.
- 이름이나 값이 숫자처럼 보인다는 이유만으로 굴림 항목으로 추정하지 않는다.
- 반복 구역 안에 메모 필드가 함께 있어도, 굴림 버튼이 참조하지 않는 메모를 검색 별칭이나 굴림 대상으로 쓰지 않는다.

## 5. 명령어와 검색

- PL이 자주 쓰는 시트 명령은 `!!굴릴항목이름` 형식으로 실행한다.
- `!!비밀 굴릴항목이름`은 현재 시트의 같은 굴림을 GM에게 보낸다.
- 일부 이름이 하나만 일치하면 바로 실행하고, 여러 개가 일치하면 통일된 검정 선택 버튼을 보여준다.
- `!!검색 이름`은 현재 캐릭터의 일치 항목과 현재 수치를 보여준다.
- `!!상태`는 PL용 항목·수치 현황, `!!점검`은 GM용 인식 상태로 분리한다.
- 사용자 화면에는 내부 변수명, 해시, `mode-...`, 원시 선택값을 노출하지 않는다.
- 굴림 항목은 기능치·판정, 무기, 주문, 광기, 기타 주사위처럼 이해하기 쉬운 범주로 정리한다.
- 사용자 안내문에는 개발 내부 용어를 쓰지 않는다.

## 6. 주사위와 선택 방식

- `!!r 2d6+3`처럼 안전하게 검증된 자유 주사위 식을 지원한다.
- 잘못된 식, 과도한 주사위 수, 닫히지 않은 식은 샌드박스를 중지시키지 않고 사용자 오류로 안내한다.
- 보너스·패널티가 분리된 시트와 하나의 선택기로 합쳐진 시트 모두 원본 선택지를 읽어 실행한다.
- `실시간`, `요약`, `일시적`, `장기적`은 현재 시트에 실제로 같은 굴림이 있을 때만 실행한다.
- 성공 단계가 있는 굴림은 실제 결과의 성공 단계를 판정 컷인 연결에 제공한다.

## 7. 수치 변경 안전장치

- 일반 채팅의 `hp+3` 같은 문자열은 수치를 바꾸지 않는다.
- 일반 채팅에서 수치를 바꾸려면 `:hp+3`처럼 명시적인 접두사를 사용한다.
- 시트 헬퍼가 값을 바꿀 때도 현재 캐릭터에 실제로 존재하는 속성만 변경한다.
- 없는 속성을 새로 만들어서 기능을 흉내 내지 않는다.

## 8. 자동 상태 처리

- 자동 처리 대상도 특정 시트 변수명이 아니라 원본 화면의 표시명, 같은 자원 묶음, 원본 굴림과 실제 저장값으로 찾는다.
- 현재 이성, 시작 이성, 최대 이성은 서로 다른 값으로 보존한다.
  - 현재 이성: 실제 판정과 손실 뒤 수치
  - 시작 이성: 진행 중 손실 비율과 장기적 광기 기준
  - 최대 이성: `99 - 크툴루 신화`로 계산되는 회복 상한
- 이성 표시 비율은 최대 이성이 아니라 시작 이성을 분모로 쓴다. 최대 이성은 별도 상한으로 표시한다.
- 시작 이성 대비 누적 손실이 5분의 1 이상이면 원본 시트에 실제 장기적 광기 상태가 있을 때만 활성화한다.
- 한 번에 이성이 5 이상 줄고 장기적 광기가 활성화되지 않았으면 원본 지능 굴림을 한 번 실행하고, 성공했을 때 원본의 일시적 광기 상태만 활성화한다.
- 한 번의 체력 피해가 최대 체력의 절반 이상이면 원본 중상 상태, 중상 상태에서 체력이 0 이하이면 원본 빈사 상태를 활성화한다.
- 필요한 상태나 굴림이 없거나 같은 뜻의 항목이 여러 개면 임의 선택하지 않고 자동 처리를 생략한 이유를 GM에게 알린다.

## 9. 검증 기준

- 정적 문법 검사만으로 완료 처리하지 않는다.
- 실제 원본 시트 파일을 파싱한 결과와 런타임 검색·실행 결과를 대조한다.
- 최소한 다음 동작을 자동 검사한다.
  - 사용자 기능 `테스트` 추가 후 `!!테스트` 실행
  - 사용자 기능 이름·수치 변경 즉시 반영
  - 사용자 기능 삭제 후 검색·실행 대상에서 제거
  - 사용자 무기와 주문 추가 후 원본 형식으로 실행
  - 반복행의 메모·설명은 굴림 목록에서 제외
  - 원본 굴림 버튼에 연결되지 않은 HP·MP 등 일반 수치는 굴림 목록에서 제외
  - 원본에 없는 특수 굴림은 표시·실행하지 않음
  - 최대 이성 99, 시작 이성 50처럼 두 값이 달라도 장기적 광기와 백분율은 시작 이성 기준
  - 시작 이성 50에서 현재 이성 41→40이면 장기적 광기 활성화, 지능 판정 없음
  - 시작 이성 50에서 현재 이성 50→45이면 지능 판정 한 번, 성공 시 일시적 광기 활성화
  - 장기적 광기가 이미 활성화됐으면 5 이상 손실에도 지능 판정 없음
  - 최대 이성만 바뀌거나 이성이 회복될 때 광기 자동 판정 없음
- 자동 검사 뒤 Roll20 Sheet Sandbox에서 실제 시트를 교체해 화면과 채팅 결과를 확인한다.
- 실방 검증 전에는 GitHub 기본 브랜치나 배포본에 합치지 않는다.

## 10. 기본 완료 조건

다음 네 가지는 다른 확장 기능보다 먼저 지켜야 한다.

1. 시트별 고정 실행 분기 제거
2. 실제 굴림 버튼에 연결된 사용자 추가 반복행 복구
3. 원본 굴림 버튼에 연결되지 않은 메모·설명·HP·MP 등 비굴림 데이터 제외
4. 실제 `coc.html` 기반 추가·수정·삭제 자동 검사 통과

광기 별칭, 화면 분류, 판정 컷인도 위 네 항목을 깨뜨리지 않는 범위에서만 유지한다.
